# План: качество RAG-ответов (зарегистрировано 14.10.2026 по итогам живых тестов)

**Источник наблюдений:** контрольные вопросы «что такое им40» / «что такое фоб» / follow-up «а какие риски по нему?» в режиме «База ВЭД» после деплоя 14.10.2026 (контейнер 066d6eb, база 111 чанков).

**Статус:** план; в приоритете после закрытия живых тестов деплоя.

---

## 1. Промпт: ответ на заданный вопрос, а не на все источники

**Наблюдение.** На follow-up «а какие риски по нему?» ответ слил определение ФОБ + риски + обязанности + сравнение с FCA. Причина двойная:
- системный промпт содержит «Если предоставлено несколько источников — используй их все и укажи, чем они дополняют друг друга»;
- в контекст попадает 5 чанков (top_k по умолчанию), среди них балласт по соседним словам.

**Правка (rag_engine.py, RAG_SYSTEM_PROMPT):**
1. Заменить «используй их все» на «используй только те источники, которые отвечают на заданный вопрос; лишнее из контекста игнорируй».
2. Ответ строится вокруг вопроса пользователя: дополнительные сведения — только если они явно запрошены («расскажи подробнее»).

**Критерий приёмки:** на узкий вопрос ответ содержит только суть вопроса; балластные чанки из списка источников не просачиваются в текст.

## 2. История диалога: убрать двойную вставку

**Наблюдение.** История передаётся модели одновременно двумя способами (rag_engine.py):
- как «История диалога: …» внутри пользовательского промпта (history_block);
- как отдельные сообщения через `messages.extend(history[-6:])`.

**Правка (rag_engine.py):** оставить один механизм (отдельные сообщения в chat-истории), убрать `history_block` из промпта. Сокращает расход токенов и путаницу модели.

**Критерий приёмки:** поведение follow-up не меняется (тест «а какие риски по нему?»), расход токенов на промпт снижается.

## 3. Шапка-отказ: применять только к пустому контексту

**Наблюдение.** Системный промпт требует дословную шапку «По имеющейся базе ответа не нашёл…». Модель применяет её и тогда, когда часть контекста релевантна, но конкретный термин отсутствует (ответ про ФОБ получил шапку-отказ лишь потому, что ИМ40 в контексте не было). Выглядит противоречиво.

**Правка (rag_engine.py, RAG_SYSTEM_PROMPT):** уточнить формулировку: шапка-отказ — только если ни один источник не даёт ответа на заданный вопрос; если часть темы есть, дать её без шапки и отдельно оговорить, чего в базе нет.

**Критерий приёмки:** ответ «что такое фоб» без «им40» в контексте не начинается с шапки-отказа.

## 4. Приветствие в поисковом запросе (после подтверждения по логам)

**Наблюдение.** Голосовой вопрос «привет что такое ФОБ» получил отказ при том, что «что такое фоб» отвечается корректно. Подозреваемый — «привет» в запросе расшатывает retrieval. Требуется подтверждение по логам (handle_rag_qa … q=…).

**Правка (work_bot.py, handle_rag_qa):** отрезать приветствия (привет/salut/здравствуйте) перед передачей в Retrieval; на приветствие отвечать короткой репликой отдельно, без RAG.

**Критерий приёмки:** «привет что такое ФОБ» отвечает как «что такое фоб»; на «привет» бот здоровается без вызова LLM.

## 5. Переписывание follow-up: не тянуть непроявленную прошлую тему

**Наблюдение.** После безответного «что такое им40» модель в ответе на новый вопрос явно цитировала склейку «им40 фоб» — повисший без ответа вопрос она пыталась закрыть вместе с новым. Retrieval при этом получил чистый запрос (эвристика в work_bot.py:341 корректно не трогает вопросы с «что такое») — то есть смешение происходит только на уровне генерации ответа.

**Правка:** пункты 2 и 3 выше снимают симптом. Если после них модель продолжает тянуть прошлые темы — добавить в промпт правило «отвечай только на текущий вопрос; упомянутые ранее темы без ответа не поднимай».

**Критерий приёмки:** новый самодостаточный вопрос отвечает без пересказа прошлых неотвеченных.
